# Beloved website

Static, JavaScript-free site generated by `build.py`:

| Output | Contents |
|---|---|
| `index.html` | Home: what Beloved is, how it works, features, Screen Time access and limits, why Beloved, privacy, accessibility and control. A download button appears only with a real App Store URL; otherwise an honest "not yet available" note |
| `faq.html` | 15 answers checked against the app |
| `support.html` | Requirements (iOS version read from `Config/Shared.xcconfig`), troubleshooting, bug-report instructions, contact |
| `privacy.html` | Generated from the policy the app bundles (`App/PrayerLock/Resources/Legal/PrivacyPolicy.md`) |
| `terms.html` | From `content/terms.md` — **needs legal review before publishing** |
| `404.html` | Not-found page (noindex) |
| `robots.txt`, `sitemap.xml` | Production: crawlable, with an https sitemap. Preview: `Disallow: /`, no sitemap |
| `_headers` | Security headers (strict CSP with no scripts, nosniff, no-referrer, HSTS, frame denial) |
| `assets/` | `site.css`, favicon, touch icon, 512 px icon (Open Graph image) |

Every claim must match the shipped app. Publish only once approved content ships (the site
describes prayers, scripture, mantras and duas), and confirm the accessibility sentence on a
device first.

## Owner values (never invent these)

Copy `site.example.json` to `site.json` and replace every value. The template's values use the
reserved `.example` domain and the word EXAMPLE, so a production build rejects them.

| Key | Required | Notes |
|---|---|---|
| `domain` | yes | `https://<host>`, the domain you control, no path |
| `support_email` | yes | A mailbox you have set up and tested |
| `legal_name` | yes | Copyright holder / provider named in the terms |
| `terms_effective_date` | yes | e.g. "1 November 2026" |
| `contact_address` | no | Only if legally required in your jurisdiction |
| `app_store_url` | no | Real `https://apps.apple.com/<cc>/app/<name>/id<number>` link, once live |
| `governing_law` | no | Sentence supplied by your lawyer; the section is omitted otherwise |

## Build and verify

```bash
python3 website/build.py --config website/site.json
```

A production build refuses to run while a required value is missing or is an example. Every
build runs `check.py` (links, anchors, assets, metadata, no scripts or inline styles, no
placeholder or local values, robots/sitemap consistency) and fails if it finds a problem.

Preview without real values (gaps highlighted, noindex):

```bash
python3 website/build.py --config website/site.example.json --preview
```

Tests (19 cases, temporary folders only; includes a local-server run of `verify_live.py`):

```bash
python3 -m unittest website/test_site.py -v
```

## Publish (reproducible)

The build needs only Python 3 — icons are pre-generated in `static/assets/` (refresh them on a
Mac with `python3 website/build.py --refresh-icons` if the app icon changes). Values can come
from `site.json` or from environment variables, so nothing personal has to be committed:

| Environment variable | Same as config key |
|---|---|
| `BELOVED_DOMAIN`, `BELOVED_SUPPORT_EMAIL`, `BELOVED_LEGAL_NAME`, `BELOVED_TERMS_EFFECTIVE_DATE` | required |
| `BELOVED_APP_STORE_URL`, `BELOVED_CONTACT_ADDRESS`, `BELOVED_GOVERNING_LAW` | optional |
| `BELOVED_CLEAN_URLS` | `true` on Cloudflare Pages |

### Option A — Netlify (recommended; config is in `netlify.toml`)

1. netlify.com → Add new site → Import from Git (push this repository first) **or** Deploy
   manually by dragging `website/public/` after a local production build.
2. For Git deploys `netlify.toml` already sets: build `python3 website/build.py --config-env`,
   publish `website/public`. Add the `BELOVED_*` variables under Site configuration →
   Environment variables. A missing or example value fails the build, so nothing wrong is published.
3. Domain management → add your domain, follow Netlify's DNS instructions, and let it issue
   the HTTPS certificate. Turn on "Force HTTPS".

### Option B — Cloudflare Pages

Build command `python3 website/build.py --config-env`, output directory `website/public`,
environment variables as above **plus `BELOVED_CLEAN_URLS=true`** (Pages serves `/privacy` and
redirects `/privacy.html` there, so canonical URLs must match). `_headers` is applied automatically.

GitHub Pages is not recommended: it ignores `_headers`, so no security headers would be sent.

### After deploying

```bash
python3 website/verify_live.py https://<your-domain>              # Netlify
python3 website/verify_live.py https://<your-domain> --clean-urls # Cloudflare Pages
```

It checks every page answers 200 over HTTPS with the security headers, robots/sitemap/assets
load, unknown pages return 404, `http://` redirects to `https://`, and no preview build was
deployed, that each page is really the Beloved site (not a parked domain), that HSTS is
sent, and reports an unreachable site as a failure. Then:

1. Set the URLs in `Config/Shared.xcconfig` (or git-ignored `Config/Secrets.xcconfig`); `//`
   starts an xcconfig comment, so write `https:/$()/`:

   ```
   PL_SUPPORT_URL = https:/$()/<your-domain>/support.html
   PL_PRIVACY_POLICY_URL = https:/$()/<your-domain>/privacy.html
   ```

   (Cloudflare: `/support` and `/privacy`.) The release gate rejects non-https or placeholder values.
2. Enter the same URLs in App Store Connect (Marketing URL: the home page).

`website/public/` is generated output (git-ignored). Rebuild whenever the privacy policy or
terms change, and update the policy *before* releasing any version that handles data
differently.
